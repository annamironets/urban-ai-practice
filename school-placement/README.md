# Размещение школ · Советское городское поселение

Локальное браузерное приложение сравнивает обеспеченность населения местами в школах для вариантов размещения новых школ по кварталам. Оно повторяет конкурентное распределение спроса и вместимости из BlocksNet, а не вычисляет дефицит простым вычитанием.

## Запуск

Для расчёта требуется Python 3.10–3.12 и совместимая с исходной практикой версия BlocksNet — `1.0.0a9`. Если в проекте практики 2 уже есть окружение `.venv-blocksnet`, используйте его без повторной установки:

```powershell
cd C:\Users\User\ai-course\school-placement
..\python-package-boilerplate\.venv-blocksnet\Scripts\python.exe app.py
```

Откройте в браузере <http://127.0.0.1:8765>. Остановка сервера — `Ctrl+C`.

Если окружения ещё нет, из корневой папки проекта практики 2 выполните предусмотренную там установку BlocksNet 1.0.0a9 для Python 3.12, затем запускайте приложение командой выше. Приложение не скачивает городские данные и не обращается к платным сервисам или языковой модели: необходимые файлы находятся в `data/`.

Для создания отдельного окружения можно установить зафиксированные зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py
```

Для проверки кода:

```powershell
..\python-package-boilerplate\.venv-blocksnet\Scripts\python.exe -m unittest discover -s tests -v
```

## Работа с приложением

- Выберите квартал нажатием на карту, задайте вместимость и добавьте школу. Повторите для всех школ сценария, затем нажмите «Рассчитать сценарий».
- Режимы карты показывают исходную обеспеченность, результат выбранного сценария или изменение дефицита по кварталам.
- «Разместить автоматически» независимо проверяет все 814 кварталов для одной школы заданной вместимости. Таблица ранжирует варианты по сокращению суммарного дефицита. Ошибки расчёта отдельных кварталов отображаются; при ошибках результат не называется лучшим среди всех кварталов.
- Нажмите строку автоматического поиска, чтобы показать этот вариант на карте. Сценарии можно сохранить в браузере, сравнить в таблице, сбросить и выгрузить результаты по кварталам или таблицу автоматического поиска в CSV.

## Данные и метод

Источники — сохранённые результаты практики 2 в `python-package-boilerplate/data/sovetsky/`: `blocks.geojson` (геометрия и ID кварталов), `sovetsky_pipeline_results.csv` (оценка населения по зданиям и вместимость школ по кварталам), `accessibility_walk_minutes.csv` (матрица пешего времени), `blocks_school_provision.geojson` (контрольный результат BlocksNet) и `school_occupancy.csv` (источник вместимости существующей школы). Копии, использованные приложением, находятся в `data/`; исходные файлы практики 2 не изменяются.

Параметры взяты из `service_types_config["school"]` установленной версии BlocksNet: норматив расчётной потребности — 120 мест на 1 000 жителей, порог пешей доступности — 15 минут. Спрос по кварталу округляется вверх способом BlocksNet; сначала используется вместимость собственного квартала, затем оптимизационная модель BlocksNet распределяет доступные места между кварталами с учётом матрицы времени. Каждая новая школа прибавляется к существующей вместимости своего квартала. Входные оценки населения, норматив и матрица доступности между сценариями не меняются.

При запуске приложение проверяет версию BlocksNet, соответствие ID кварталов геометрии и строкам/столбцам матрицы, а также совпадение исходного повторного расчёта с сохранёнными результатами практики 2. Сравнение — модельная оценка пространственной обеспеченности, а не выбор земельного участка. Возможность строительства требует отдельного градостроительного обоснования.

## Публикация

GitHub Pages обслуживает только статические файлы и не запускает `app.py`. Корневой `render.yaml` в репозитории содержит настройки для развёртывания Python API на Render. Создайте Blueprint из этого репозитория и примените конфигурацию:

- Root Directory: `school-placement`
- Build Command: `pip install -r requirements.txt`
- Start Command: `python app.py --host 0.0.0.0 --port $PORT`
- Переменная `SCHOOL_PLACEMENT_ALLOWED_ORIGINS`: `https://annamironets.github.io`

Для публикации интерфейса задайте в настройках GitHub репозитория Actions variable `SCHOOL_PLACEMENT_API_URL` равной HTTPS origin созданного API, например `https://your-service.onrender.com` (без завершающего `/`). Существующий workflow документации добавит интерфейс по пути `/school-placement/` и запишет этот API-адрес в конфигурацию Pages. После успешного запуска workflow приложение будет доступно по адресу <https://annamironets.github.io/urban-ai-practice/school-placement/>.

Render и другие сторонние хостинги могут менять условия бесплатного тарифа; проверьте доступность выбранного тарифа при создании сервиса. Не добавляйте адрес API с HTTP: браузерная страница GitHub Pages работает по HTTPS и заблокирует небезопасные запросы.
